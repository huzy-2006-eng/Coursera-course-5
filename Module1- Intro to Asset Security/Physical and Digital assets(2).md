## DATA - Information that is translated, processed, or sorted by a computer.

# STATES OF DATA:
1. Data in use - Data being accessed by one or more users.
{when you are in a park and u stop and check your email.}

2. Data in transit - Data travelling from one point to another.
{when ur friend sends u a mail and u read it and then send a reply, so now data is in transit}

3. Data at rest - Data not currently being accessed.
{when u finish checking an email and then close the laptop, so the data is now at rest.}

Information Security(InfoSec) - The practice of keeping data in all states away from unauthorized users.

# CLOUD BASED SERVICES:

1. ## Software as a Service(SaaS) - 
SaaS refers to front-end applications that users access via a web browser. The service providers host, manage, and maintain all of the back-end systems for those applications. Common examples of SaaS services include applications like 
Gmail™ email service, Slack, and Zoom software.

2. ## Platform as a Service(PaaS) -
PaaS refers to back-end application development tools that clients can access online. Developers use these resources to write code and build, manage, and deploy their own apps. Meanwhile, the cloud service providers host and maintain the back-end hardware and software that the apps use to operate. Some examples of PaaS services include
 Google App Engine™ platform, Heroku®, and VMware Cloud Foundry. 

3. ## Infrastructure as a Service(IaaS) - 
IaaS customers are given remote access to a range of back-end systems that are hosted by the cloud service provider. This includes data processing servers, storage, networking resources, and more. Resources are commonly licensed as needed, making it a cost-effective alternative to buying and maintaining on premises.

Examples - 
Google Cloud Platform.
Microsoft Azure.

# CLOUD SECURITY:
1. Cloud security is a growing subfield of cybersecurity that specifically focuses on protection of data, applications, and infrastructure in the cloud.

2. For example, a PaaS client pays to access the resources they need to build their applications. 
So, it is reasonable to expect the to be responsible for securing the apps they build. 
On the other hand, the responsibility for maintaining the security of the servers they are accessing should belong to the CSP because there are other clients using the same systems.

## In cloud security, this concept is known as shared responsibility model.
It includes:
 Identity and access management.
 Resource configuration.
 Data handling.

# CLOUD SECURITY CHALLENGES:

## Misconfiguration
is one the biggest concerns. Customers of cloud-based services are responsible for configuring their own security environment.
Oftentimes, they use out-of-the-box configurations that fail to address their specific security objectives.

## Cloud-native breaches 
are more likely to occur due to misconfigured services.

## Monitoring access might be difficult
 depending on the client and the service.

## Meeting regulatory standards
is also a concern, particularly in industries that are required by law to follow specific requirements such as HIPAA,PCI,DSS and GDPR.
